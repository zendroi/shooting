# Railway Deployment Guide

## Quick Deploy

1. **Connect to GitHub**
   - Go to [Railway Dashboard](https://railway.app)
   - Click "New Project" → "Deploy from GitHub repo"
   - Select your `zendroi/shooting` repository

2. **Automatic Setup**
   - Railway will automatically detect Laravel
   - The `railway-setup.php` script will run during build
   - All environment variables will be configured automatically

3. **Environment Variables**
   Railway will automatically set these variables:
   - `APP_KEY` - Generated automatically
   - `APP_URL` - Set to your Railway domain
   - `DB_CONNECTION=sqlite` - Using SQLite for simplicity
   - All AWS/Slack/Postmark variables set to empty (no warnings)

## Build Process

The deployment will run these commands automatically:

1. **Install Dependencies**
   ```bash
   composer install --no-dev --optimize-autoloader --no-interaction
   npm ci
   ```

2. **Build Assets**
   ```bash
   npm run build
   ```

3. **Setup Environment**
   ```bash
   php railway-setup.php
   ```

4. **Cache Configuration**
   ```bash
   php artisan config:cache
   php artisan route:cache
   php artisan view:cache
   ```

5. **Start Server**
   ```bash
   php artisan serve --host=0.0.0.0 --port=$PORT
   ```

## Troubleshooting

### Environment Variable Warnings
If you still see warnings about missing environment variables:

1. **Check Railway Variables**
   - Go to your project in Railway dashboard
   - Click on "Variables" tab
   - Make sure all required variables are set

2. **Redeploy**
   - Go to "Deployments" tab
   - Click "Redeploy" to run the setup script again

3. **Manual Fix**
   - Add the missing variables to Railway environment
   - Set them to empty string if not needed

### Common Issues

1. **"APP_KEY is not set"**
   - The `railway-setup.php` script should generate this automatically
   - If not, manually set: `APP_KEY=base64:your-32-char-key`

2. **"Database connection failed"**
   - SQLite database will be created automatically
   - Check if `database/` directory is writable

3. **"Assets not loading"**
   - Make sure `npm run build` completed successfully
   - Check if `public/build/` directory exists
